# TUI 设计全面审视与开发备忘录

> 日期：2026-07-25  
> 范围：`/tui/` 工作台、信息架构、运行时元数据、首页、AI 助手、MCP 自助接入、治理工作区及键盘交互  
> 目标：让普通用户先完成业务任务，让管理员按治理对象处理问题，同时保留终端式高密度与键盘效率。

## 一、审视结论

当前 TUI 已具备统一导航、元数据驱动表单、Dashboard、任务分层和键盘操作，但仍有一批设计从“工具目录”而不是“用户任务”出发。主要问题不是视觉风格，而是角色边界、主任务显著性、导航可预期性和字段呈现语义。

必须优先解决的四项问题：

1. 1024px 左右的两列 Dashboard 在奇数面板时会生成非法 `grid-template-areas`，最后两个面板可能重叠。
2. 普通用户能看到或触达治理摘要与管理员入口，首页角色边界不清。
3. 收藏、进度、最近工作区等状态共用浏览器键，切换账号后会互相污染。
4. GET/只读任务沿用“执行、提交”语言，用户无法直观看出动作是否会改数据。

## 二、不符合操作习惯的设计

### 1. 首页和响应式布局

- 自适应网格在 981–1180px 的两列区间没有保证每行区域数一致。
- 首页同时暴露投研摘要与治理摘要，普通用户容易把系统异常误认为个人待办。
- 待办表格展示类型、内部 ID 等实现字段，事项、状态和下一步反而不够突出。
- 顶部长期显示 `PUBLISHED / OPERATE / JSON DEBUG`、screen 地址等技术信息，占用首屏注意力。

### 2. 任务与动作语义

- 一个屏可聚合 80–90 个动作，虽然已有任务分组，但默认密度仍像 API 目录。
- 只读 GET、创建、更新、切换、删除和长任务没有稳定的公共动作语义。
- 复杂 JSON/object 参数落入单行输入框，默认值会显示成 `[object Object]`。
- 金额、比例、置信度、时间等值缺少统一的人类可读格式。

### 3. AI 助手

- “AI 助手”的第一视图是待人工处理任务，不是稳定可见的消息输入。
- 用户需要进入左侧任务区才能找到对话动作，违背聊天产品的首要操作习惯。
- 对话结果、任务队列和待人工处理没有形成清晰的主次关系。

### 4. MCP 自助接入

- 未生成令牌时，页面先强调完整接入包，首次使用者不知道从哪里开始。
- Token、Endpoint、Prompt 已有专门语义，但“创建—复制—验证—回收”的顺序仍不够明确。
- 没有可复制 Token 时仍可能出现复制/显示控件，空状态误导。
- MCP 工具治理和用户接入治理混在同一管理员屏，治理对象不同。

### 5. 导航与可访问性

- 工作区变化不进入浏览器历史，URL 不能复制到某个具体 screen。
- 浏览器前进/后退与 TUI 工作区状态脱节。
- 弹出菜单缺少完整的 `menu/menuitem` 语义、方向键循环和 Escape 焦点归还。
- 收藏星标点击目标偏小，读屏名称不包含工作区名称。
- 页脚长期平铺大量快捷键，关键动作和低频动作没有分层。

### 6. 治理工作区

- AI 服务商治理与用户配额治理混在同一屏。
- MCP 能力/工具治理与用户令牌/开关治理混在同一屏。
- 管理员需要先理解内部模块结构，而不是按“治理对象”进入任务。

## 三、实施方案

### 阶段 A：P0 稳定性与角色边界

- 修复自适应 Dashboard 奇数面板两列布局。
- 为 screen、panel、action 增加并执行 `audience` 投影。
- 首页普通用户隐藏系统治理入口和数据任务面板，管理员保留。
- 收藏、进度、最近工作区、首选主线和恢复标记按用户命名空间存储。
- 发布 `effect = read/create/update/toggle/delete/execute`，按钮使用查看、创建、保存、切换、删除、执行等明确动词。

### 阶段 B：主任务重构

- 首页列只保留优先级、状态、事项、下一步等任务字段。
- AI 助手增加 P0“开始对话”入口，待人工处理降为 P1。
- MCP 首屏改为“创建令牌—完整接入包—验证—令牌历史”。
- 写动作面板不自动提交，点击后定位到对应表单。
- 默认首屏任务密度降为 5 个主操作、4 个任务组；复杂屏允许小幅放宽。
- AI 服务商/用户配额、MCP 能力/用户接入分别成屏。

### 阶段 C：导航、字段和可访问性

- 使用 `?screen=<screen_key>` 建立可复制深链接。
- 成功切屏写入 History；`popstate` 恢复对应工作区。
- 普通用户隐藏 screen 调试地址；管理员保留。
- object/list/json 自动使用多行 JSON 编辑器，所有结构化值安全序列化。
- Regime 置信度统一显示为百分比。
- 菜单补齐 ARIA、方向键、Home/End、Escape 焦点归还。
- 收藏按钮扩大至 36px，并包含目标工作区名称与 `aria-pressed`。
- 页脚仅保留高频快捷键，完整快捷键保留在 F1 帮助中。

### 阶段 D：验证与收口

- schema、Application 元数据、Infrastructure runtime injection、前端 renderer 同步更新。
- 将默认字段别名注册表拆到独立 Application 模块，保持 metadata 校验器低于治理行数上限。
- 增加普通用户/管理员契约测试。
- 增加 981、1024、1180、1280、1440 宽度的 Dashboard 防重叠测试。
- 增加 URL 历史、账号存储隔离、对象渲染和菜单焦点浏览器测试。
- 使用真实登录态对首页、AI 助手、MCP 自助接入和治理工作区做视觉复核。

## 五、完成标准

- 981–1440px 的关键 Dashboard 不重叠且不产生页面级横向溢出。
- 普通用户目录、首页面板和 action payload 不含管理员治理能力。
- 同一浏览器切换用户不会继承另一用户的收藏、进度或最近工作区。
- 所有 read 动作不再默认显示“提交”；创建、更新、删除等副作用可直接辨认。
- AI 助手打开后无需搜索任务即可开始输入问题。
- MCP 新用户能按单向流程完成令牌创建、接入包复制和验证。
- 复制带 `screen` 参数的 URL 可直接进入目标工作区，浏览器后退可恢复上一工作区。
- 页面不出现 `[object Object]`；关键比例、置信度和结构化字段可读。
- TUI JavaScript 回归、TUI Python 单元回归、布局守卫和真实浏览器视觉审查通过。
