# Financial publication capacity gate

The workflow has three explicit stages. `qualification` is the ordinary N=1 contract check: it freezes one deterministic asset/date pair only when the isolated database already contains typed AKShare source-time evidence written by the controlled S6 dual-capture path. It independently revalidates both retained bodies and their RawAudit links. Legacy `available_at` or `announced_at` values never qualify.

`capacity_rehearsal` is the separate, explicitly approved full-workload measurement. It runs only in the isolated environment, freezes the complete active asset universe, and requires an exact owner-authenticated database ceiling whose manifest digest, maximum slices, and maximum requests equal the full frozen manifest. Any missing or mismatched ceiling blocks before provider egress. Its successful receipt records the measured full workload. A qualification receipt always has stage `qualification` and can never authorize formal start, even when the isolated manifest has one slice.

The formal production workflow independently freezes the complete active asset universe and requires a trusted typed AKShare source-time fact for every active asset. Missing evidence blocks before provider egress. Formal start accepts only a successful `capacity_rehearsal` receipt with the identical full-manifest digest, then requires a reviewed production ceiling bound to the exact runtime provider, contract, parser, deployment region, policy, candidate, receipt, and manifest. The workflow rechecks that binding and ceiling before each provider slice and before atomic policy-v3 activation.

S6 now emits a required `financial_scope_capacity` report from the existing isolated scope-discovery stage. It covers every active financial asset with two independently retained provider bodies and RawAudit identities per asset, derives a source revision and separate evidence/artifact ledger hashes, and records the full logical and physical request ceilings. The receipt binds the exact source-report SHA, candidate image, release provider-identity digest, release universe, financial universe, and a scope-pointer digest. Its nested discovery report and encrypted artifact graph travel in the bundle so the validator can recompute the hashes and check freshness, path safety, complete coverage, and zero fact/publication writes.

This S6 stage uses its own pre-egress scope-discovery owner event. It does not claim production `data_owner` plus `independent_reviewer` approval, and it does not create a production owner ceiling. The receipt is a content-hash graph carried across the trusted handoff boundary; it is not a cryptographic signature or proof of source identity. Production formal publication still requires exact production-side review and an approved owner ceiling. The market `full_universe_capacity` report and the N=1 `akshare_financial_slice` report remain separate evidence and cannot establish full financial scope capacity.

All three task stages use durable checkpoints with a lease on each in-flight slice. A live duplicate delivery reads the current checkpoint without changing it or repeating provider work. After claim expiry, the workflow records an indeterminate outcome and keeps the orphan claim evidence; it never replays that slice automatically. Each AKShare dual capture uses one route candidate in capacity workflows, so a slice uses at most its two approved logical provider requests.

Ceilings are deployment database records entered from an externally reviewed payload. The superuser entry command requires the payload's approving owner to differ from the authenticated recorder; it cannot synthesize approval evidence. The admin can inspect and revoke an approval, but cannot append one or reactivate a revoked record. Production manifests stream typed-evidence rows in bounded batches, keep only the latest valid source-time fact for each active asset, and stop with a stable block if an asset exceeds the per-asset scan guard.

The global typed-evidence scan guard is 600,000 rows. It is calibrated above the observed production snapshot of 487,624 rows while remaining a fail-closed resource ceiling; increasing it requires a new production-scale measurement and review. The guard limits evidence discovery only and does not relax the requirement for one valid, current, typed AKShare source-time fact per active asset.

Generic current-publication rebuilds own only quote, price, and valuation. Their preview and execution result explicitly identify `equity.financial.fact` as deferred with `financial_capacity_receipt_required`; repair and backfill report `partial` while preserving successfully committed market pointers and completed market progress. Any explicit generic financial selection fails before candidate lookup or publication transaction, and the generic financial batch/canonical publisher reject financial execution with stable code `FINANCIAL_CAPACITY_RECEIPT_REQUIRED`. These generic paths do not create financial candidates, current-pointer changes, audit events, or outbox events. `prepare_candidate()` remains a read-and-build boundary for the dedicated formal workflow, which stages and activates only after the full-scope capacity receipt and authenticated production approval checks succeed.
