# 券商成交导入与余额核对合同

本合同随 ASH03 成交保全业务批次实施；在该批次完成验证与提交前，不代表运行环境已经具备下列行为。主计划见 [§19.77](../plans/a-share-usability-implementation-plan-2026-10-16.md)。

## 入口与选择

复用现有经过身份与交易权限校验的入口：

| 用途 | 入口 | 请求 |
| --- | --- | --- |
| 文件预览 | `POST /api/account/broker-trades/preview/` | multipart，CSV / XLSX / XLS |
| 文件确认 | `POST /api/account/broker-trades/import/` | multipart，同一原始文件 |
| TUI 预览 | `POST /api/account/tui/broker-trades/preview/` | JSON，UTF-8 CSV 文本 |
| TUI 确认 | `POST /api/account/tui/broker-trades/import/` | JSON，同一 CSV 文本 |

继续接收 `portfolio_id`、`broker_name`、`file`。确认增加以下可选参数：

| 参数 | 含义 |
| --- | --- |
| `baseline_decision` | `pending`（默认）、`included` 或 `excluded` |
| `baseline_as_of` | 可选的 aware 余额有效时刻；未提供时保留未知，不猜券商时钟 |
| `expected_fact_set_fingerprint` | 明确 included/excluded 时回传本次预览的事实集合依据 |
| `expected_balance_fingerprint` | 明确 included/excluded 时回传本次预览的本地余额比较依据 |

`pending` 保存真实成交事实，持仓等待核对；不要求先取得当前报价、历史 PIT、可卖量或外部来源资格。`included` 表示本次展示的整份文件已计入展示的本地余额，不再加减数量或生成交易镜像。`excluded` 表示尚未计入，仅在事实范围和余额比较通过后尝试经济数量投影。空仓、旧字段默认值、历史日期或上一批导入成功都不能替代本次声明。

TUI 保持已有预览和确认两个操作。两个表单的文件不自动继承；确认时需重新选择刚预览的同一 CSV。预览依据经现有隐藏续接机制传递，不要求用户查看、复制或填写哈希。SDK 普通预览结果公开两个机器字段，供后续代码调用回传。MCP 保持既有预览、确认与请求幂等流程，不能用确认令牌或请求幂等键代替余额比较依据。

预览和确认回执的证券名称只读取本地规范主数据；查不到名称时仍展示证券代码。展示回执不触发行情抓取、名称补全写入或外部供应商访问。

## 事实、状态与重试

`TransactionModel` 是券商成交的唯一实际事实记录。源成交时刻与本地记录时刻分别保留；缺失费用为未知，明确的零费用为已知零。每个首次保存的事实保留源行、稳定键和首次文件/批次出处。重试不得改写原经济字段、原始行或首次记录时间。

| 状态 | 含义 |
| --- | --- |
| `not_applicable` | 普通非券商核对记录 |
| `legacy_unverified` | 升级前的券商记录，旧余额及镜像来源尚未核实 |
| `awaiting_baseline` | 事实已保存，等待余额包含关系声明 |
| `projection_pending` | 已进入待投影流程，尚无成功投影证明 |
| `projection_blocked` | 事实保留，投影有明确待处理原因 |
| `projected` | 本次明确未包含的经济数量已投影 |
| `already_in_baseline` | 已明确包含，零数量增减 |

重复稳定键须比较经济内容和范围。同键相同事实返回原记录，待处理状态允许重新核对；终态不得再次产生数量增减或交易镜像。同键不同经济内容属于冲突，保留原记录并返回原因。没有券商成交编号时，现有摘要键只提供原合同下的去重依据，不能证明券商的两个完全相同成交本来就是同一笔；不为本批静默更换键算法。

重新取得预览也不能反转已完成状态：已投影的事实仍为 `projected`，不得以 `included` 改标；已确认含在基线中的事实不得以 `excluded` 再次投影。重导保留原声明、投影证据、持仓数量和交易镜像，历史成交原件不被新声明覆盖。

旧 `legacy_unverified` 行本片只允许显式确认 included。excluded 必须保留来源限制及待处理原因，不能在第一次失败改变状态后于第二次重试绕过限制。逐事实核对详情保存声明与尝试依据，批次计数或错误列表只是摘要；重建批次摘要不能消除待处理事实。

## 余额与失败语义

事实持久化、余额投影和推荐匹配使用分开的事务范围；它们仍服从外层调用方已有的事务，不声称可以越过调用方回滚。投影或匹配失败不能在导入用例内部擦掉已保存事实。批次摘要失败与事实写入失败分别报告，数据库未成功写入时不能报告事实已保存。

预览依据绑定账户所有者、组合、文件原始字节、实际事实集合及精确经济字段。余额比较依据绑定本地映射、持仓身份和数量等实际字段；每次读取产生的展示时刻不参与比较。确认时在锁内重新核对，文件或余额变化时保留真实事实、拒绝数量投影，并引导重新预览。

事实集合变化返回 `BROKER_FACT_PREVIEW_CHANGED`；余额变化返回 `BROKER_BALANCE_PREVIEW_CHANGED`。相应 HTTP 409 响应仍须携带事实保存结果，调用方不能把 409 当作“数据库没有记录任何成交”。缺失必要确认参数属于输入校验错误；该错误与已经保存事实后的比较冲突分开。

数量投影回滚后，阻断状态在后续事务中按所有者和组合重新加锁保存；逐行回执与汇总使用实际更新后的行，不能使用回滚前的 ORM 快照。已完成终态继续保持，阻断原因与原声明、源成交时刻和本地知识时刻分别保留。

`facts_saved_count` 表示本请求中先前返回成功的首次写入操作数。若随后发生删除、归属变化或读取失败，行回执为 `fact_unavailable`，错误码为 `BROKER_FACT_CURRENT_STATE_UNAVAILABLE`；不发布旧核对状态，也不计入四项当前状态数量。逐行与汇总使用同一份读取结果，不重新统计未请求的核对结果；系统不为凑齐回执重建成交或持仓。TUI 提示先核对文件与余额再重试，不能将先前写入成功视作当前仍可读取。

实际 SELL 投影验证经济总数量，不复用新模拟卖单的可卖量权限判断。总数量不明确、映射歧义或将产生负数量时保留事实并阻断投影；可卖量不因此变为已知。历史成交价不升级为当前报价，现金没有余额依据时不假称已完成对账。新资产类别只能使用明确本地元数据与既有规则，不能按代码前缀或默认股票猜测。

此数量投影只接受明确的 `equity`、`fund` 或 `fixed_income` 分类。`other`、`commodity`、`derivative`、`cash`、`currency` 等历史宽泛分类不能借用旧映射默认值转成股票或基金；缺少可信分类时保存成交并给出投影阻断原因。旧接口的兼容映射保留其原有行为，不为该严格投影入口授予分类资格。

统一持仓另用 `valuation_known` 表示估值是否已知。首次历史 BUY 没有现价时，数量和成本可入账，数值零只作必填字段的存储占位；用户持仓输出的价格、市值及浮动盈亏为 null，`valuation_status="unknown"`。既有参考估值的 True 兼容值不是 freshness 证明。通用保存不授予估值资格，实际成交数量投影也不要求估值先变为已知。

未知估值同时传播到用户和观察员持仓、账户卡片、资产与收益汇总；已知现金和成本信息仍可查看，依赖估值的汇总为 null。裸价格刷新不认证未知持仓，也不把占位数值写成完整账户敞口；自动买入风险检查返回 `POSITION_VALUATION_UNKNOWN`。

BUY 成本使用独立保存的总成本、成交金额与明确已知费用计算，不能先舍入单位均价再重建总成本。SELL 按独立总成本分摊剩余成本；本地余额均价不能用来声称已知历史成交的实际已实现收益，成交镜像的历史收益保留 null。费用完整性仍以规范事实的逐项 known 标记为准，缺失费用不得视为已知零。旧持仓本地创建日期也不能认证券商首次买入日。

已存在旧账本持仓与统一持仓但没有准确来源映射时，核对必须受阻，不能仅因证券相同而合并或覆盖。全清仓撤销指向已删除持仓的活动映射，核对详情保留退役持仓的来源与目标 ID，实际成交和交易镜像继续保留。

## 现金、成本与绩效的知识状态

数量投影不认证现金。模拟账户保留模拟账本现金；real 账户标为 `cash_known=false`，核对状态为 `unverified` 或 `quantity_only`。本批没有将 real 账户现金转为已核实的入口。原现金数值保留，但当前余额、总资产及依赖它们的绩效读取为 null；自动买入风险与依赖现金的策略返回明确阻断。持仓数量及独立已知的估值、成本仍可查看。

持仓和成交镜像另发布 `cost_basis_known`，成交镜像同时发布 `fee_amounts_known`：True 表示完整已知，False 表示明确不完整，None 表示历史未知。已知费用小计不等于完整费用；缺失项不补零认证。现有行的 `quantity`、`avg_cost` 或 `total_cost` 变化且未传入知识状态时，旧 True 降为 None；False 保持 False，通用合并不将历史 None 升为 True。新行按显式输入初始化。

已实现收益与胜率只使用已执行 SELL，且每条成本、费用均完整、实际收益非 null；待执行、取消或失败订单不进入胜率分母。存在不完整已执行 SELL 时，已实现汇总及胜率保持未知。收益率、年化收益、回撤和 Sharpe 还依赖现金与全部持仓估值已知；顶层和嵌套绩效均传播 null。任务结构化摘要保留 null，邮件区分现金/估值缺失和成交成本缺失。未知当前余额不抹除独立可计算的已实现胜率。

每日净值在现金、持仓估值或所需成交成本不完整时返回 blocked，保留稳定原因；该净值用例的阻断分支不写账户绩效或每日净值历史/快照，调用方保留阻断结果。自动退出的价格/收益阈值要求对应估值及成本已知；独立的证伪与建议检查沿用原规则。

## 升级、回退与验收边界

0068 只增加核对状态和详情并分类旧券商行，不重写经济字段、费用、源/本地时刻或原件。只有 `not_applicable` / `legacy_unverified` 且详情为空的可重建分类允许删除字段；新业务状态或非空声明存在时拒绝回退。不能以旧代码忽略这些信息为安全回退方案。

Sim 0031 只增加兼容默认的估值知识标记，不回写旧经济字段；有未知估值行时拒绝删除该标记。忽略标记的旧代码不是安全的代码回退。

Sim 0032 只分类现金知识并保留原现金和时钟；存在 real 账户、未知现金或非模拟账本状态时拒绝删除该知识。0033 为历史成本/费用保留 None，不改写经济数据；存在任一 None/False 状态时拒绝删除知识字段。PostgreSQL 回退检查在原子迁移内锁定涉及表，不能跳过保护直接删列。

本地迁移、并发及 HTTP/SDK/TUI 测试分别记录真实输入与结果。本合同不确认生产券商余额、现金、T+1 来源、Owner M2/M3、真实账户启用或实盘下单资格。
