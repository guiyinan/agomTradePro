## 1. 目标与完成边界

围绕“判断数据是否可用 → 筛选标的 → 管理持仓 → 形成调仓清单 → 人工执行或受控 QMT 执行 → 对账复盘”，补齐 A 股实际使用中的交易语义和用户闭环。

优先解决已经核实的错误与不一致，再补组合约束、事件和效果反馈。复用现有 Data Center、Evidence、Risk、Portfolio、Broker 和 TUI 能力；不以新增模型数、治理报告数或研究算法数作为完成标准。

### 1.1 分别验收三种可用性

| 层次 | 用户可以完成的任务 | 必须满足的条件 | 不随此层验收获得的能力 |
| --- | --- | --- | --- |
| A：投研与人工交易辅助 | 查看可用行情和财务、筛选、分析持仓、形成明确受限的调仓清单、导入真实成交并对账 | 输入时间与能力边界明确；交易数量与成本合理；研究禁用状态可见；普通用户完整旅程通过 | 不自动开通 QMT，不把研究专用结果升级为决策依据 |
| B：可信模拟与历史评估 | 按目标证券规则模拟交易、查看净成本后的结果、复现历史可得信息 | A 股交易日、结算、成交约束、公司行为、成本、PIT 和历史股票池通过对应验收 | 不把日线可成交假设当成真实成交，不替代券商环境验证 |
| C：QMT 正式执行 | 获批账户在明确范围内提交、撤单、接收成交、恢复并对账 | 精确 Evidence/风控授权、即时重校验、真实目标 Windows/XtQuant、连续仿真、小额实盘与恢复验收全部通过 | 不扩展到两融、期货期权或自动扩大实盘规模 |

A/B 可独立交付；C 的未完成状态必须显式展示。任何层次均不得消费被标记为不可用于决策的数据。人工在外部券商的实际成交可作为事实补录，即使原建议已失效，也应保留事实与异常说明，不能反向宣称原建议当时有效。

### 1.2 首期支持范围

1. 以人民币普通现金账户、已明确交易权限的 A 股股票为第一验收范围，覆盖沪深主板、科创板、创业板及北交所的规则差异。
2. 交易能力逐板块验收。未验证的板块可保留研究展示，执行侧必须明确不可用，不能因为同属 A 股而默认放行。
3. 场内 ETF 按具体证券的交易、结算与价格规则另行列入支持矩阵；不能统一套用股票 T+1。场外基金申赎不纳入本计划的股票订单流程。
4. 首期执行以限价单为主。开收盘集合竞价、盘后固定价格等阶段必须识别；未实现的阶段明确拒绝。识别阶段不等于承诺首期支持其下单。
5. 港美股、融资融券、衍生品、全自动策略晋级和 R1–R8 算法扩展不在本轮范围；旧表删除和整库账本搬迁不作为前置条件。

### 2.1 交易规则依据

规则实现前须核对当时有效正文、特别规定、暂缓实施条款和券商实际能力。以下是本计划核查入口，不是运行时配置或完整规则清单：

- [上交所修订说明](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml)。例如主板风险警示股票涨跌幅限制调整，说明规则不能永久固定为历史常量。
- [深圳证券交易所交易规则发布通知](https://www.szse.cn/www/lawrules/rule/stock/t20260424_620190.html)及其现行正文、特别规定。
- [北京证券交易所交易规则发布公告](https://www.bse.cn/jygl_list/200028217.html)及其实施安排。

具体费率、证券交收、分红税处理、投资者权限和券商接口字段还需对应官方文件及目标券商确认。每个规则版本保留来源、有效区间与核验时间；没有可靠来源的值不得用经验常量填充。

### 4.1 与现有主线的关系

- DATA-18 / DATA-02 / DATA-03：继续负责数据恢复、真实来源与发布验收。本计划消费能力报告，不修改全范围或源时间要求来获得通过。

- 版本退役及 Data Center 旧事实访问合同继续生效；业务闭环验收不等同于旧表可删。

### 4.2 建议实施批次

1. 第一批：ASH-01，随后 ASH-02、ASH-03、ASH-04；先证明规则、账本和数据边界正确。

5. 第五批：依既有 QMT 与 Evidence 条件执行 ASH-12。外部等待不阻塞独立的 A/B 改善。

同一 repository 主线按机器焦点串行整合，允许的生产/外部/治理取证按既有授权进行。工作量和日历日期在 ASH-01 盘点后估算；真实交易日、观察窗口和券商权限耗时不承诺为固定开发天数。

| 市场会话 | 市场日期、开闭市、节假日、临时休市、集合竞价/连续竞价/盘后阶段、下一可执行会话 | data_center 证据端口 |
| 即时交易状态 | 源报价时刻、停复牌、有效价格边界、无边界的明确依据、申报价格范围所需参考值 | data_center 与受校验的券商边界输入 |
| 账户能力 | 当前账户、证券/板块权限、可用资金及股份、冻结量、状态时间、来源 | account 身份、portfolio 投影及 broker_execution 券商事实 |
| 判定结果 | allowed、稳定阻断码、用户说明、适用版本/证据、有效期、需重验条件 | risk_center Application 输出 |

名称为概念，实际类型与表优先复用现有定义。规则入库提供初始化和管理入口；生效区间不得重叠歧义，缺失规则拒绝执行。Domain 不访问网络、ORM 或运行配置。

### 6.2 实施任务

1. 提取纯规则判定，分别处理买卖数量、零股清仓、整数要求、价格档位与上下限；禁止 QMT 适配器用 int 转换静默截断非法数量。
2. 将“有边界”“经证实无边界”“未知边界”分为不同状态。无法证明状态时拒绝执行，不能以零或空值代表不受限制。
3. 交易日和阶段从有来源的会话证据读取；停止以星期一至五替代交易日。时区明确为 Asia/Shanghai，外部时间标准化后进入 Domain。
4. 独立校验停牌状态、账户权限、报价时效和有效申报范围。达到涨停/跌停不直接等于禁止申报或保证成交；可申报和预计可成交分别表达。
5. 服务端形成规则版本/内容摘要绑定的执行约束；Agent 使用同源约束或可验证规则投影。缺失、漂移或过期拒绝提交，不能两端各自维护常量。
6. 在计划计算、模拟撮合、回测、创建和最终提交入口使用同一契约。规则改变、账户权限或报价状态改变时重新计算，不静默改动已批准订单字段。

退出门：边界与反例测试通过；同输入的服务端和 Agent 判定一致；声明支持的板块均有证据。无法获得某板块真实接口数据时保留其执行禁用，不以 mock 声称真实支持。

## 7. ASH-03：结算、预留和费用

### 7.1 账本语义

- 分开记录经济持仓、已结算/可卖股份、未结算当日买入、卖单冻结；避免把“总持仓”和“可卖”赋为同一值。
- 按每个成交批次及证券结算规则计算释放，跨节假日沿真实交易会话推进；同日买入、部分卖出、加仓和撤单均不能制造可卖股份。
- 区分账面现金、交易可用现金、委托冻结资金和可取资金。买单预留包含明确的费用预算；实际费用到账后释放差额，不能重复冻结。
- 在数据库事务内维护订单、预留及账本变更；并发订单不能消费同一份可卖量或资金。释放按订单/成交/事件幂等执行。
- 正常模拟成交遵守规则；真实成交导入以券商事实为准，超出计划或异常交易记录待核对，不能丢弃事实。修正用可审计冲正/补记，不覆写历史成交。

### 7.2 费用与历史存量

1. 复用现有费用配置，核查佣金、最低佣金、税费、过户费、滑点与市场冲击的所属语义，按证券、方向、账户及生效日期应用；数值全部有来源，金额使用 Decimal。
2. 正常交易入口使用相同成本计算。实际费用已在成交导入中给出的，保留实收值及分项，不再次估算扣款；未知费用不能默认为已确认的零。
3. 区分统一持仓维护/真实导入镜像与现金驱动的模拟订单，公开标明零费用镜像的用途及实际费用来源，不把它当成免成本模拟成交。需要模拟平仓的调用方转用普通卖单及同一 FeeConfig；不得对镜像再次收费，API/SDK/UI 引用同步核查。
4. 历史 available_quantity 不在代码启动时自动重写。先生成只读差异预览，按有来源的成交/结算证据制定有界修正，保留备份、原值及回滚点。
5. 异常停机后从持久化预留、券商事实及成交幂等键恢复，不因本地缓存丢失重新释放或重复成交。

退出门：昨天 300 股、今天买入 200 股的 T+1 用例，以及跨休市、零股、部分成交/撤单、费用预算不足、重复回报、并发抢占、事务回滚全部通过。正常模拟与同输入回测采用一致的结算和成本语义。

## 8. ASH-04：数据能力与新鲜度

1. 沿用 Publication 和 PIT 端口，把源观测时间、源可用时间、基准日、获取时间、freshness、reliability、must_not_use_for_decision、稳定阻断原因贯通至消费者。
2. 日终研究与盘中下单分别定义数据需求：已闭市日线可用于声明范围内的研究，不能充当盘中执行报价。Agent 行情必须保留源时间、证券身份、市场会话和状态证据。
3. 财务选择遵守知识截止点；报告期、公告日、可用时间各司其职，date-only 源按已批准合同处理，不捏造分秒或用采集时间替代披露时间。
4. 每个资产输出可用能力：行情研究、技术评分、财务估值、计划计算、下单等依赖分别评估。财务缺失禁用依赖财务的功能，仍可展示已验证的行情。
5. 完整保留冻结范围和 requested/succeeded/failed/stored；partial 财务报告不升级为 full-scope Publication，不通过删除失败资产缩小分母。
6. 局部供应商/资产失败可以局部禁用；身份、授权、审计链或范围完整性错误按现有合同阻断受影响整体动作，不能借“局部继续”绕过可信性检查。
7. 数据源 failover 保留一致性校验、源时效和单位；stale 结果继续尝试后续源，无可靠结果就显示具体缺口。
8. TUI 首屏显示“最近已收盘交易日”“盘中观测时间”“仅供观察”“财务不可用”等用户语义，明确下一步，不只显示绿色同步成功。

退出门：未来财报、旧 Qlib 缓存、交易日切换、部分资产失败、stale failover、未知来源时间、缺源行情时间的执行请求均有反例；读取无隐式刷新/回填。真实发布能力由 DATA 主线和 ASH-11 分别验收。

## 9. ASH-05：公告、公司行为与持仓事件

### 9.1 优先事件

优先核查财报披露/修订、业绩预告与修正、风险警示/退市状态、停复牌、现金分红、送转与配股；其次考虑解禁、减持、回购等持仓提醒。数据来源与权限先验证，不能因有 RSS 新闻就宣称事件链完整。

### 9.2 实施任务

1. 复用现有 events 与 data_center 事实结构，核对业务职责后补齐证券身份、来源事件 ID、公告/可用/生效时间、修订关系和原文证据。未知事件映射 UNKNOWN 并记录日志。
2. 事件按资产及账户产生影响：推荐重新评估、旧计划失效或需重审、执行限制、持仓/现金调整。事件不能无条件触发自动交易。
3. 公司行为按股权登记、除权、生效和到账等不同阶段处理；送转股份的可卖日、配股的资金与操作、分红税的适用与后续扣缴按真实规则建模，未知状态待核对。
4. 将现金和股份事件作为可重放账本条目，按事件 ID、修订版、账户和生效阶段幂等；更正用冲正/后继事件，重复抓取不重复分红。
5. 区分未复权价格、复权收益序列和现金/股份事件。不能同时使用含分红的收益序列又重复记现金股利；实时委托、成本核对使用正确的实际价格口径。
6. 复用统一 Audit/Outbox 和通知机制；事实更新、账本变更与派发边界可恢复，通知失败不重复入账。

退出门：同一事件重复到达、晚到、更正、先公告后生效、送转零股、配股未参与、税费后扣、账户隔离及除权收益连续性金样本通过。源覆盖不足的事件明确保留缺口，不自动保证全部事件齐全。

## 10. ASH-06：回测真实性

1. 明确 formation cutoff、信息可用时间、下单时间和成交时段。日线收盘后形成信号只能在规则允许的后续时点执行，不在同一收盘价上偷用该信号。
2. 调仓日期先按策略频率生成，再根据版本化交易日历及策略约定映射到会话；明确遇休市向前还是向后，不以请求日期作为已成交时间。
3. 历史股票池保留上市、退市、风险状态与历史成分变更；不能用今天存活的股票列表回测全部历史。
4. 使用 PIT 财务、修订版本和公开可用时点；预测特征、标准化、训练和筛选均不得看到截止点之后的信息。
5. 接入同一规则、结算与成本契约。仅日线数据不能证明排队成交，涨跌停/停牌及无成交量时采用明确且保守的撮合假设，并发布其局限。
6. 输出 submitted、filled、partially_filled、unfilled 和原因；止损触发与实际卖出分开，未成交持仓继续估值和暴露风险，不凭空变成现金。
7. 校验成交额/成交量单位与参与率；费用、滑点、冲击按每次实际交易计算，买卖两侧口径一致，基准也按所声明口径处理。
8. 净值含未平仓市值、真实现金流、公司行为和成本；研究结束日没有有效成交条件时保留持仓，不能强制无成本清算。输出毛收益、净收益、换手、回撤、超额与未成交影响。
9. 可信等级由数据覆盖、PIT、规则、成本和成交模型证据决定；无法证明的部分标为受限，不能仅因测试通过宣称可实盘。

退出门：至少包含普通换仓、节假日、当日信号次日成交、一字涨跌停、连续跌停止损失败、停牌估值、退市、财报晚到和分红送转的固定金样本。未来信息扰动不改变过去结果，相同输入重放结果一致；与正常模拟的相同场景结果可对账。

## 11. ASH-07：组合风险与资金调度

1. 在现有有效风险策略中补版本化行业集中度、成交容量和在途委托约束；先盘点已有同类规则，保留原有总仓位、单股、现金和硬排除。
2. 行业分类及成分带来源/有效时间；ETF 持仓披露有时滞，穿透结果必须标明覆盖和日期。缺失部分不得当作零暴露或精确实时持仓。
3. 计算“当前持仓 + 有效买卖预留 + 拟新增订单”的预期暴露；未成交卖单不能提前当作已经降低风险或释放全部资金。
4. 容量约束使用明确成交额/量窗口、可用日期、参与率和单位；数据缺失或停牌时阻断依赖流动性的执行，阈值来自业务配置。
5. 压力测试复用现有 Scenario 用例，优先覆盖行业同步下跌、连续跌停、停牌无法退出与流动性下降；明确已持久化的运行证据及尚需补齐的结果明细。
6. 风险判定同时在计划生成和最终执行重验；限额变更或其他委托占用发生后，旧计划不能继续凭历史“通过”执行。

退出门：多只同行业股票、股票与 ETF 重复暴露、过期穿透数据、多订单抢占、卖单未成交、低流动性与连续跌停情景均有解释和阻断结果。先交付可解释的暴露与退出约束，高级 VaR 不作为首期完成条件。

## 12. ASH-08：账户调仓与 TUI 主任务

### 12.1 调仓清单

每条计划至少呈现当前数量/可卖、目标数量、买卖股数、价格口径及时间、预计分项费用、成交后现金、适用规则/风险版本、有效期、证伪条件和阻断说明。

1. 从目标权重生成满足数量、现金、成本和容量约束的可行股数；展示取整后权重偏离和剩余现金，不把无法执行的零股建议直接下发。
2. 明确卖出与买入依赖。只有真实可用资金满足条件才允许买入，卖出未成交时保留等待状态；现金不足不能无限自动缩单。
3. 复用 TransitionPlan、精确订单绑定和审批 artifact。计划修改影响已审批字段时生成后继版本并重新审批，不能就地篡改。
4. 部分成交、撤单、过期、规则变化和断连恢复后，基于成交事实重新计算剩余计划。旧批准不自动授权新的剩余数量或价格。
5. 无正式执行能力时允许形成合格的人工清单和成交导入旅程，但必须显示“未开通系统下单”；数据被禁用于决策时不得生成伪可执行清单。

### 12.2 用户体验

- 复用已发布 TUI 屏幕和任务导航；一个 screen 一个主任务，发布 primary_task、primary_outcome 和必要 default_action_key。
- 盘前入口回答数据是否可用、事件是否需处理、持仓风险和下一操作；调仓入口回答能买卖多少、为什么受限；盘后入口回答成交和账本是否对齐。
- 普通用户首屏见关键资金/股份、数据时间、阻断及下一步；实现路径、回执字段和网络错误细节放管理/诊断面。
- API、SDK、MCP 与界面使用相同服务、账户权限和读写边界；契约覆盖状态码、Content-Type、空数据、部分可用和越权场景。
- 本计划不新建 Classic 业务主页面，不把所有操作继续堆入一个通用 API 工具页。

退出门：普通用户完成“查看持仓 → 解释限制 → 生成计划 → 部分执行/导入 → 查看剩余 → 对账”的浏览器旅程；只读用户不能写入，越权账户不可见；空数据和阻断状态都有可行动说明。

## 13. ASH-09：正式执行授权接线

1. 先核查现有订单 approval artifact、pre-risk scope、plan-order binding、账户绑定、风险授权和 Evidence 适配器完整定义，列出真实缺失连接。
2. 复用 canonical receipts 和当前 authority；将具体账户、租户、owner、计划/订单版本、内容 hash、规则/风险策略与有效时间绑定，拒绝自由 JSON 或调用方自报 passed。
3. 在 create、approve、lease、submitting 四个节点验证对应条件。审批后撤权、策略变更、报价失效、数量/价格漂移、账户更换或租约失效均阻断。
4. ASH-02/03 的规则、实时资金/可卖量和预留检查不能被正式回执替代；授权有效也不代表订单此时仍可交易。
5. 不把当前 gate 简单改为 true 或增加通用 bypass。只有精确范围的完整链路具备可验证接入和验收条件才可考虑受控启用；未覆盖路径保持拒绝。
6. Agent 提交异常进入不确定状态，先查询和对账，不盲目重试；本地日志、服务端事件与券商回报应在重复/乱序下收敛。
7. 回归 kill switch、断连、重启、审批失效、部分成交后撤单与撤单拒绝。恢复后不自动复活过期计划，也不自动解除人工停止状态。
8. 记录 `decision → create → approve → lease → submitting → broker_ack → partial_fill/fill/reject/cancel → reconciliation` 的最小执行事件链；各适用节点保留订单、计划、账户和审批版本、源事件时间、本系统接收/记录时间、事件序列或幂等标识及时钟来源。券商未提供源时间时保留 `None`，不得以本机接收时间冒充券商 ACK 或成交时间；断连恢复按订单事实和事件序列对账，不仅凭本地日志推断。

仓库退出门：全部正例及上述负例在隔离环境通过，真实 PostgreSQL 并发/回滚无跳过；没有完整证据的请求仍稳定拒绝。此完成不等于 EVID/QMT 生产验收，不触发真实下单。

## 14. ASH-10：真实账户复盘

1. 先对齐初始资产、入出金、分红、费用、成交和期末估值，区分投资收益与外部现金流；按任务明确时间加权或资金加权口径。
2. 建立推荐/计划/委托/成交的精确 lineage；保留现有绑定。手工交易无法精确对应时保留 match_method、置信度和人工确认，不强行归因给最近推荐。
3. 分开显示市场/行业/选择及仓位贡献、实际费用、实施差额和未成交机会成本。比较价格须晚于信号可用时点并有可得性依据。
4. 将证伪触发、用户采纳/忽略、退出时点和异常原因纳入复盘；可估计值和不可识别部分显式标注，归因残差不能藏进“其他收益”。
5. 对账未完成、事件遗漏或费用未确认时降低报告可信度，提示具体待办；不能因生成日报成功就宣称账本正确。
6. 建立版本化执行质量报告，区分决策价、到达价、委托价与实际成交 VWAP；每个基准价格保留来源、源观测时间和可用时间，明确买卖方向符号、费用是否计入、成交/未成交数量及机会成本，分别呈现价格滑点、实收费用、延迟成本和未成交影响。缺基准或时间证据时输出 `unavailable/limited`，不得以零滑点或当前价回填历史基准。

退出门：收益与账本、基准和成本分项在声明精度内勾稽；入出金、重复导入、部分成交、分红和无法关联的手工交易均有金样本。执行质量报告的基准、方向、费用和精度口径可复算，证据不足时明确降级。报告普通用户可理解并能回到具体成交或事件。

## 15. 验收矩阵与质量门禁
