## 1. 产品范围与不可改变的条件

近期目标仍为 A 股研究、可读模拟调仓计划、手工辅助下单及事实对账。真实自动下单的后续产品许可按 [Owner approval-log 第 8 项后续澄清](../reviews/owner-scope-freeze-2026-10-18/approval-log.md) 保留：默认关闭、用户主动开启、真实账户/来源/风险/审计资格齐备。QMT/ASH-09/12 等仍 deferred，不作为 M1 前置，也不因本计划恢复。

资金与数量、费用、T+1/可卖量、来源时钟、PIT、账户范围、令牌撤销、幂等及回滚保持现有合同。可读研究、可用于决策、可模拟执行、可真实执行是不同资格；不能用一个 publication pointer 或一个 bool 合并。

新增结构须能对应当前用户主任务或已复现的故障；先说明既有对象为何无法承载。新增 Vn 必须同时列出旧版读写入口、迁移/兼容方案与退役目标。不为提高计数、扩大算法目录或证明治理本身新增表。当前已冻结的 M1 风控/账户 API 批次按已有门禁收口，不追溯判作违规，也不为本轮评审重跑无关 QA。

## 3. 工作包与验收

### REF-01：现状、增量约束与可退役清单（WP0、WP5 盘点）

复用 `build_data_dictionary.py` / `check_data_dictionary.py`、`module_map`、已有架构增量检查和 `governance_baseline.json`。本次静态快照在评审回复中；实施时核定抽象声明、具体模型、数据库实表、声明字段和继承字段各自口径，不能混用。

按模型族登记当前 writer、current/exact/history reader、CLI/Admin/SDK/MCP/原始 SQL、触发器/FK、部署开关、存量数量及归档消费者；未知使用保持未知。只存必要的去标识计数、版本与路径，不把用户记录、token 或密钥写进证据。为第一族给出停写、迁读、兼容期、删除和回滚点。

在已有 CI/字典增量检查入口补“新增模型/版本说明”和差值校验，不新建审批服务、独立基线文件或手工编辑生成投影。两迭代是停止无边界旧版扩展的目标，不是强制删数据期限。首批退出为：清晰口径、一个可实施退役族、实际运行的增量门与正反例；仅本次规划不能算退出。

### REF-02：账户族与业务 owner 收敛（WP1、WP5）

职责映射按评审回复 §5：account 身份，portfolio 组合/持仓/流水，risk_center 风险，data_center 标准事实。模拟和真实账本物理隔离，simulated_trading 保持执行编排；在现有结算适配器完整验收前不搬表、不变更迁移 app_label/FK。

优先选择 REF-01 证明外部依赖最小的旧 owner-assignment/authority 族，**不得默认最大 Vn 已替代所有旧版**。步骤为特征测试 → 通过公开 Application 端口单写入 → 停止旧写入 → 带旧 ID/hash/as_of 的只读影子比对 → 切读与兼容回滚 → 核对存量/恢复 → 删除旧入口及适用表。不得双写两套可变账本，不改历史 migrations，不回填虚构时钟。

净删除先报告实际值；不以 account≤15 或“只剩三张授权表”为退出门。新增中间结构须有明确撤除路径，不能用 V6 替代退役工作。保留只读令牌、账户范围、撤销与已被实际使用的分享合同。

### REF-03：合格读取边界与存储主从语义（WP2、WP3）

复用已有 Publication 和各 owner 的 typed Query Service/Protocol。研究原件默认不能被决策或执行用例直接取得；合法读入口核验用途、来源观测/可得时间、版本、scope、freshness、撤销和完整性。静态禁止跨层依赖之外，增加通过公开 API/SDK/MCP 的旁路反例；不能把 import 扫描当完整证明。

每族选择一个规范原件，其他列定义为可重建的只读查询投影。若现有原件就是 canonical_payload，允许 typed codec 解码、重放和冲突拒绝；结构化列为原件的模型则停止业务读取第二份 payload。封印按具体威胁和替代校验逐项处置，不只按“外部/内部”分类删除。

外部 `must_not_use_for_decision`、freshness、reliability、稳定 blocked reason 等合同保持。删除内部冗余 flag/seal 前，必须有等价的未发布/错误账户/过期/撤销/未知/篡改反例；不得把缺字段当 False。目标是消除旁路和独立双写，不是 flag=0、seal表≤10 或 rg 找不到 payload。

### REF-04：R4/R5 生命周期试点（WP4）

第一事项只抽取确定性的状态转移、前缀重放、事件次序与幂等机制，放在 research Domain 内。R4 宏观/R3/Portfolio record、R5 固收结果集的类型、策略与验证保留；不把业务规则放 shared，不用无类型 JSON 消解差异。

原 API/Facade 和存储保持，双轨仅作同输入只读对比。共用状态机测试覆盖边界，同时保留每个 R 的业务测试。试点证明减少重复实现后，再估合表收益、迁移身份、归档消费者与 rollback。R6/R7 特有对象保留，后续 R 扩展以实际收益和使用需求决定；不承诺 research≤35。

### REF-05：Regime 增量价值的有界实验（WP7 验证）

先盘点既有数据能支持的历史 PIT 区间：宏观原始发布日期、修订/首次 known_at、市场价格/公司行为和交易日历。只在真实可得区间实验；修订后现值不能冒充历史已知值。资料不足则给出“不能识别增量价值”的范围和补采办法，禁止以新购数据作为 M1 前置。

预先固定研究假设、参数选择规则、walk-forward 训练/验证/样本外窗口、成本、可交易时间和缺失处理。比较同一股票池/同一底层策略“无 Regime / 有 Regime”；另列买入持有宽基和简单动量/均线基准。保留空仓、不可成交、换手及双方费用假设，报告 OOS 收益/超额、最大回撤、换手、样本数、区间/敏感性与局限。HP 只用扩张窗口，Kalman 参数遵守既有 Domain 合同。

复用现有 experiment/MultipleTestFamily 标识；原件记录数据、配置、代码、种子/确定性、运行命令及 hash。失败/无增量也是有效结论，决定后续 regime/policy 投入，不自动晋级或交易。此任务是独立研究可行性/有界实验，**不是恢复 deferred ASH-06 的完整交易回测工程，也不满足 STRAT-02 或 ASH-11**。

### REF-06：明文退役与默认拒绝复验（WP6）

先验证现有 key encryption 命令、读写 fallback 和新写入路径；只统计待迁移数量，不输出密钥。加密必须有往返解密、失败不毁原值、幂等重跑和兼容恢复测试。数据迁移验证后才移除 plaintext fallback/字段；源码有列不能证明现网有值或已泄露。

复用现有 Publication PostgreSQL、authority generation 和账本测试：SQLite 快速测试继续保留，statement trigger/并发/ACL/迁移/恢复在隔离 PG 必跑且不得 skip。此处不新建第二个全量 CI 系统。

核对执行模式、binding 的主动开启、can_trade/approve、账户范围、freshness、撤销、lease/reconnect 与 kill switch。缺 TradingControl 行不等于禁用；所有取单/提交/重试/直接端点必须由正向资格链拒绝未启用账户。可选 app/feature flag 只有在迁移、导入和路由依赖清楚后实施，先降低入口暴露并保留手工事实导入。
