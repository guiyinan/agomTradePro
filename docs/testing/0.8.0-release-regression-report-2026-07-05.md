### Notes

- TUI runtime metadata split preserved the published repository contract while reducing the size of `apps/terminal/infrastructure/tui_metadata_repository.py`.
- The follow-up phase also converted runtime injections to structured bundles backed by feature-scoped injection modules, so new runtime screens/actions no longer require custom repository-side injection branches.
- The next follow-up converted runtime screen patches and action patches to feature-scoped modules plus registries, so repository runtime normalization now depends on registries instead of large patch dictionaries.
- The workbench follow-up split `apps/terminal/application/tui_workbench.py` into a thin service shell plus focused constants, catalog helpers, and result-model helpers while preserving the module-level monkeypatch surface used by `test_tui_workbench.py`.
- The readiness follow-up split `show_personal_readiness_status.py` and `validate_personal_readiness_window.py` into thin command wrappers plus focused management helper modules while preserving the command-level test surface.
- The governance baseline was tightened by removing the historical large-file allowance for `tui_metadata_repository.py`.
- The governance baseline was tightened again by removing the historical large-file allowance for `tui_workbench.py` after the service shell dropped below the 1200-line limit.
- The governance baseline was tightened again by removing the historical large-file allowances for the two readiness command wrappers after they dropped below the 1200-line limit.
- Version/build alignment was completed for the `0.8.0-build.20260705` release line.
