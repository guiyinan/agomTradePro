# A 股读取 CI：事务清理与序列化恢复修复

股票池提交 165afa4135aeab08b855fed10cac425fce7a17bc 的实际 Fast Feedback 失败，Python 3.11 和 3.13 均为 **2528 passed / 1 failed / 6 errors**。增量质量、无数据库 TDD 和另外四条工作流成功，不能据此称该提交通过。原失败日志与首次诊断另存 ci-failure-and-repro-475.zip，不会覆盖为新结果。

估值测试正例缺少明确的 must_not_use_for_decision=False，因此正式读取正确地返回空上下文。本批补全正例，断言独立交易日与观测/抓取时钟，并新增缺少门控仍为空的反例。另一个根因是 R1 事务测试清理删除了迁移创建的权限时钟单例；后续浏览器清理被既有保护拒绝。R1 现导入同一保留 fixture。仅保留单例后，浏览器清理恢复，但普通事务的 post_migrate 又与后续 Agent 序列化恢复冲突；因此五处既有事务标记采用项目迁移测试已使用的 serialized_rollback=True 模式。

修正后的只读 SQLite 探针先得到 **3 passed / 3 errors**，直接记录单例在 R1 调用期间存在、随后在浏览器调用前缺失；仅保留单例候选为 **12 passed / 1 error**，剩余错误确认为 ContentType 冲突。最终四测试文件的组合验证分别为 **SQLite 13 passed、原生 PostgreSQL 13 passed**，包含 R1、六条真实浏览器旅程、Agent 恢复和五个估值测试；这是同一组用例的两种数据库上下文，不是26个不同用例。四文件 Black、isort、Ruff 通过。第一次探针的异步上下文错误和候选 isort 失败均保留，未算作业务失败或通过证据。
