# ASH03 自动模拟交易结算与运行防重入

本批把 HTTP 自动交易入口与 15:30 Celery 任务的 BUY/SELL 接到现有结算 UoW，保留原策略与候选来源。提交基线为 `0e54384678e6b0bbddc72e4fb1088455d1c34b52`；本批不代表整项 ASH03、Owner 验收或生产就绪。

## 运行身份和重试

- HTTP 必须提供 `Idempotency-Key`，SDK/MCP 原样传递，键不进入业务请求体。相同操作重试复用同键与原输入；新的业务操作使用新键。
- Celery 专用发布器在首次 `apply_async` 时把业务键写入消息 kwargs；显式键保持不变，Celery 重试和消息重投沿用该键。直接运行或绕过发布器的调用必须显式给键。独立发布是不同操作，不声称多个 Beat 实例跨消息恰好执行一次。
- `(namespace, invocation_key)` 唯一绑定原请求；省略日期或账户列表仍保留为省略，仅第一次解析有效日期和有序账户范围。相同键改变原输入返回冲突，后续默认范围变化不会重新扩大交易范围。
- 普通 HTTP 用户在首跑和重放时重新校验账户范围；执行桥把授权用户 ID 固定传入 UoW。新读取到的账户所有者不能替代原用户；数据库锁内仍按同一个用户 ID 校验账户。管理员和可信内部任务保留原授权范围。
- 运行状态为 `ready → preparing → started → finished`。只有确定尚未进入引擎的准备失败可以凭原 claim token 释放；进入引擎前先持久化 `started`。已开始的运行不重新计算订单，也没有自动续跑、租约抢占或重置功能。
- 完成结果按严格类型持久化并重放；未完成、回执损坏或保存结果不确定时失败关闭。已有确认成交计数继续保留，不确定写入数发布为 `stored=null`。

## 单笔结算边界

自动成交复用当前用途 V2 证券身份、正式发布日历、Risk V3 规则和 Fee V2，再交给手工交易同一个结算 UoW。订单使用运行 UUID 与本次首次执行中的递增序号形成单笔幂等键；它不代表整批可恢复。

执行桥保留引擎实际使用的 `PriceLookupResult`，核对代码、请求日期、历史口径、非 fallback 和价格的一致性。日频历史价格的日期、来源和未知观测时间保持原义，不把读取时刻当作行情观测时刻。冻结执行日必须等于同一截止点的正式当前开放交易日。

每笔订单捕获同一个 aware UTC 截止点用于身份、日历和 manual/UoW 读取，锁内再次检查证据有效性。这不表示整批账户共用一个数据库或行情快照。V2 来源记录的 `source_observed_at/source_available_at=None` 与 `must_not_*` 原值保持不变，只在既有普通模拟记账用途内读取。

UoW 在事务内锁账户、持仓与待结算记录，处理到期释放、可卖数量、费用和账本变动。当天新买入形成待结算记录，不直接变成可卖数量。仓储返回后无法验证回执、成交回读失败或未知执行异常，都归为结果不确定；引擎停止该账户后续订单与绩效写入，保留之前确认成交。账户转属、停用、变为非模拟账户或所有者无法读取也停止该账户后续处理；其他已知零写入预检阻断可以继续处理后续候选。

## 迁移与回滚

`0034_automatic_trading_invocation` 只新增运行记录，不回填历史成交。任何运行记录仍存在时拒绝反向删表；PostgreSQL 在事务中取得排他表锁后检查，空表才允许 schema round trip。

代码回滚前必须停止自动入口与任务投递，并保留运行记录和成交幂等依据。旧代码会绕过本批运行保护，不能把切回旧 writer 当作安全恢复方案。已开始但结果未知的运行需要按原键核查实际账本，不能删除记录后重跑。
