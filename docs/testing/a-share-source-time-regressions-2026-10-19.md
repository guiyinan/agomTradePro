# ASH04 来源时钟与旧缓存回归

本批只补测试，覆盖既有实际执行调用、持久 Qlib 缓存读取及研究 TUI 的来源时钟。生产代码、运行配置、授权和数据发布策略均未改变；完整 ASH04、ASH03 仍开放。

QMT 用例在实际 v2 提交 envelope 中把行情 `market_observed_at` 设为 null，重算内外哈希并更新绑定，要求因 `TIMESTAMP_INVALID` 拒绝，且无服务端 ACK、本地订单状态或 fake vendor 写入。这与允许缺省的 v2 instrument identity 来源时钟不同，未改变其合同。

旧 Qlib 缓存用真实 ORM 行和公开 `CacheAlphaProvider.get_stock_scores()` 读取，显式设置现有五天阈值，验证五天仍 `available`、六天只能 `degraded` 并保留原陈旧天数及原因。降级结果的 `success=True` 只表示取得回退资料，不等于当前可用于决策；已有 stale prediction 测试另验证不会刷新推荐 workspace。

Renderer 单元和真实登录/HTTP/Application/页面旅程分别验证：缺失行情观测时间不由抓取时间补造，明确的“行情抓取时间”原值与阻断原因保留。三种既有/新增研究场景都在展开详情前检查限制和缺口完整落入视口，且页面与主面板滚动为零；初始截图使用 `full_page=False`，交互后全页图单独命名。只注入 Data Center 读取端口，不代表真实 Provider 或生产发布资格。

## 已验证范围

在精确父版本 `cfcc2f374ed520fe532d0271d865765c0bff9541` 加已冻结的私有股票池候选及本批四个测试文件组成的隔离源上：三个受影响单元模块 **116 passed**，三条真实浏览器旅程 **3 passed**；原计划 §8 的十五个有限反例另为 **15 passed**。先跑的两个精确节点包含在116中，不重复计数；不与股票池80项或较早105项相加。各命令和输入哈希见精简索引，pytest主体耗时和包含初始化的命令耗时分别保留。

原 §8 反例包括未来/未知财务可用时间、PIT 精确成员与截止、date-only 不改写历史、交易日切换、已收盘日线研究与越界行情、缺失报价时间、stale failover、旧 Qlib 来源阻止 workspace 刷新和默认股票池读取不写业务状态。它们证明各自测试合同，不扩展到全部消费者或真实源验收。

四个测试文件通过 Black、isort、Ruff；第一次格式检查的两处失败及原候选已归档。交叉静态审查发现的视口证据不足由精确位置断言及新截图补齐。六张最终截图已逐张审查，网络与 JavaScript 错误按实际回执记录；辅助治理队列503不能解释成全部HTTP成功。无生产 Python 改动，故本批不新增生产 mypy 扫描，不修改债务基线或生成投影。
