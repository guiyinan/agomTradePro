# B｜个人项目的独立复核定义

决策编号 `OWNER-20261018-B`；状态：Owner 已批准 B1 复核定义；尚无具体候选的独立复核或 Owner 签字。原回复见 [审批记录第 4 项](approval-log.md)。

**已决定：** 本目标采用“无开发对话上下文的独立 agent 复核 + Owner 签字”作为项目级独立复核。

| 选项 | 含义 |
| --- | --- |
| B1（推荐） | 独立会话 agent，无开发聊天历史；只收到冻结需求、Owner 范围、diff、源码/配置/证据和可复现命令，形成独立意见，Owner 最后签字 |
| B2 | 在 B1 之外再找一个真实人工复核者 |
| B3 | 继续等待外部独立人工，不开展相关验收 |

**已批准值：** B1 适用于当前个人研究、模拟调仓和手工导入项目。独立 agent 不读取开发对话，不继承实现者的推理与结论，不作为同一开发上下文的“第二签名”。“无上下文”不等于无需求或无证据：需求和接受标准必须完整。

**最小复核包：** Owner 决定、候选 SHA 与 diff、冻结输入/hash、实际命令及原始通过/失败记录、剩余风险/反例、权限和数据影响、回滚点。复核者能自行查看代码与重放必要证据；报告列出阻断项、非阻断项和未验证事项。实现者修复阻断后，复核者重新审受影响范围；源码或关键配置变更使旧签署失效。

**范围限制：** agent 意见不是一个真实人类身份，不充当账本里要求的 staff actor、财报来源证明、真实市场采样、券商验收或 Owner 审批字段。若系统强制两个不同真实主体，必须另改治理契约或选 B2，不能用政策文字假装机器约束已解除。

**风险：** 模型可能共享知识盲点、漏看真实环境问题或误读伪造日志。Owner 应签署报告的结论、已知局限和部署范围，而非仅签“测试通过”；高影响数据写入及首次部署仍按各自计划确认。

**回滚：** 撤回/作废本次 review receipt，保留原报告与作废原因；重新冻结候选并独立复核。已发生的业务写入按业务回滚处理，不删报告洗掉历史。
